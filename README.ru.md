binfer читает каталог файлов-образцов одного неизвестного двоичного формата и
печатает текстовый отчёт о найденных полях — с доказательством для каждого.

## Какую задачу это решает

У вас тридцать сохранений от игры или тридцать выгрузок из программы, чей формат
никто не документировал. Открыть один файл в hex-редакторе — почти бесполезно:
любой байт может означать что угодно. Открыть тридцать и сравнить — совсем
другое дело: байты, которые никогда не меняются, это структура, а байты, которые
меняются вместе, это поле. Делать такое сравнение руками утомительно и легко
ошибиться — ровно та работа, которую должна выполнять программа.

binfer выполняет сравнение и, что важнее, отказывается угадывать. Четыре
равномерно случайных байта прекрасно декодируются как 32-битное целое; в самих
байтах нет ничего против. Поэтому чтение сообщается только тогда, когда корпус
несёт за него положительное свидетельство, и каждое утверждение приходит вместе
со счётчиком, который его подтверждает.

## Настоящий отчёт

Это фактический вывод `binfer samples/` на корпусе из двадцати четырёх файлов
формата с префиксом длины и хвостовым CRC32:

```

  145..522 bytes, mean 314, median 322
  sizes are not uniform, 24 distinct sizes

LAYOUT
  OFFSET    SIZE  TYPE             VALUE/RANGE       CONFIDENCE EVIDENCE
  EOF-4        4  u32le            see checksum      proved     matches in 24/24
  0x0000       4  magic[4]         'BLOB'            high       identical in 24/24
  0x0004       4  const[4]         01 00 00 00       high       identical in 24/24
  0x0008       4  u32le / u16le    125..502          high       top 2 byte(s) zero in 24/24
  0x000C       4  u32le            547680..16515876  high       top 1 byte(s) zero in 24/24

RELATIONS
  EOF-4 u32le    checksum crc32 over the bytes before it       proved     matches in 24/24
  0x0008 u32le   length   value + 20 == size                   proved     holds exactly in 24/24

  0x0010..EOF-4      unexplained   4.21 bits/byte  nothing found accounts for these bytes

NOTES
  - sizes differ, so offsets were compared over a 72-byte head window and a 72-byte tail window; the
    span between them has no common offset and was measured but not aligned
```

Отчёт всегда на английском: его удобно вставить в форумный пост или в issue,
где читатели говорят на разных языках.

Полезная нагрузка между заголовком и контрольной суммой — это не структура,
которую binfer не сумел найти. Это блок переменной длины, в котором структуры
нет, и отчёт говорит об этом прямо, вместо того чтобы заполнить таблицу
правдоподобными строками.

## Установка

Скачайте `binfer.exe` из
[последнего релиза](https://github.com/joyboyisalive07-lab/binfer/releases/latest).
Это один файл без установщика и без зависимостей времени выполнения; работает из
любой папки, в том числе с флешки.

Либо из исходников — нужен только Python 3.12 или новее:

```bash
git clone https://github.com/joyboyisalive07-lab/binfer
cd binfer
python -m pip install -e .
```

### О Windows Defender и SmartScreen

Исполняемые файлы, собранные PyInstaller, иногда помечаются Windows Defender или
вызывают предупреждение SmartScreen. Это не особенность binfer: однофайловая
сборка PyInstaller распаковывает интерпретатор Python во временный каталог и
запускает его — такая форма поведения кажется подозрительной некоторым
эвристикам, а сам файл не подписан, потому что сертификат для подписи кода стоит
денег, которых у проекта нет. Если это для вас проблема, соберите из исходников
через `tools/build.ps1` или запускайте `python -m binfer` — они делают ровно ту
же работу.

## Использование

```
binfer <каталог>                   разобрать корпус и напечатать отчёт
binfer <каталог> --json ФАЙЛ       дополнительно записать находки в JSON
binfer <каталог> --ksy ФАЙЛ        дополнительно записать черновик Kaitai Struct
binfer --self-test                 проверить инструмент по известной ground truth
binfer --version
binfer --help
```

Флаги: `--min-confidence {low,high,proved}`, `--max-files N`, `--record-size N`,
`--no-color`.

Коды выхода: 0 — успех, 1 — анализ не смог запуститься или self-test обнаружил
регрессию, 2 — ошибка использования.

Укажите каталог минимум с четырьмя файлами; от двенадцати статистике уже можно
доверять, а при меньшем количестве отчёт сам об этом предупредит.

```bash
binfer ./saves --json findings.json --ksy saves.ksy
```

`--self-test` не требует ваших файлов. Он строит в памяти семь синтетических
форматов, у каждого из которых схема записана раньше, чем появились байты,
прогоняет по ним полный анализ и выставляет оценку:

## Уровни уверенности

Их ровно три, и каждый значит конкретную вещь.

| Уровень | Значение |
| --- | --- |
| `proved` | Выполняется на 100% образцов и опровержимо. Контрольные суммы и арифметика длин: один несовпавший образец полностью убивает находку. |
| `high` | Выполняется на 100% образцов, но опирается на статистический довод. Здесь живут догадки о типе: `u32le` — лучшее чтение этих четырёх байт, а не доказанный факт о них. |
| `low` | Выполняется на большинстве образцов, но не на всех; показывается, чтобы вы могли судить сами. Строковое поле, которое чисто декодируется в 20 файлах из 22, стоит увидеть. |

`--min-confidence` скрывает уровни ниже запрошенного — и в основной таблице, и
во вложенной таблице записей.

## Чего v1.0 намеренно не делает

- **Не угадывает размер записи.** Сегментация идёт по полю-счётчику, чья
  арифметика доказана точно, либо по вашему `--record-size`. Слепой перебор
  правдоподобных шагов — настоящая техника, но ни один здешний синтетический
  формат не подтвердил бы, что она работает, поэтому её нет в поставке.
- **Ничего не распаковывает.** Сжатый или зашифрованный участок помечается как
  высокоэнтропийный и необъяснённый. Это и есть ответ, а не пробел, который надо
  будет когда-нибудь закрыть.
- **Не ходит по указателям вглубь структур.** Указатель, попадающий на строку,
  так и называется указателем; что означает эта строка — ваша забота.
- **Не разбирает один файл.** Всё держится на сравнении образцов, поэтому корпус
  из одного файла не говорит инструменту ничего, о чём он и сообщит.
- **Никогда не пишет туда, куда вы не просили.** Ни кэша, ни временных корпусов,
  ни файла конфигурации. `--self-test` строит образцы в памяти.

## Сборка из исходников

```powershell
python -m pip install -e ".[dev]"
python -m pytest
python -m ruff check .
python tools/coverage.py
pwsh tools/build.ps1
```

`tools/build.ps1` собирает `dist/binfer.exe` и не считает сборку завершённой,
пока этот файл не прогонит `--self-test` и не восстановит ground truth всех
синтетических форматов. Бинарь, который запустился и напечатал номер версии, не
доказал ничего.

`tools/gen_corpus.py` записывает синтетические корпуса на диск, если хочется
открыть их в hex-редакторе. `tools/make_images.py` пересоздаёт изображения выше;
картинка self-test набрана из вывода, который инструмент действительно выдал.
